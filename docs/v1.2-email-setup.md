# Forward-to-brain email (v1.2 T5)

Forward or send an email to a private address and it gets captured like any note
(subject + body run through the same enrichment pipeline, `source = email`).

## How it works
An inbound-email provider POSTs the parsed mail to the app webhook:

```
POST https://obsidian-x.vercel.app/api/inbound-email?token=<INBOUND_EMAIL_SECRET>
Content-Type: application/json
{ "from": "you@example.com", "subject": "...", "text": "..." }
```

The webhook is protected two ways:
- the `token` query param must equal `INBOUND_EMAIL_SECRET` (set in Vercel env), and
- the `from` address must equal `OWNER_EMAIL` — mail from anyone else is ignored.

Also accepts form-encoded payloads and common field names (`From`/`TextBody` for
Postmark, `sender`/`body-plain` for Mailgun), so most providers work as-is.

## Option A — Cloudflare Email Routing (free, needs a domain on Cloudflare)
Use `docs/cloudflare-email-worker.js`. It parses the MIME and calls the webhook.
Set the worker secret `OBX_WEBHOOK_URL` to the URL above (with your token), deploy,
then route `brain@yourdomain.com` → the worker. This is the recommended path.

## Option B — Postmark / Mailgun inbound (no domain of your own required)
Point the provider's inbound webhook at the URL above. They deliver JSON/form
payloads with the fields we already parse. Use the provider's supplied inbound
address (e.g. `something@inbound.postmarkapp.com`) as your capture address.

## Test without a provider
```bash
curl -s -X POST "http://localhost:3000/api/inbound-email?token=$INBOUND_EMAIL_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"from":"you@example.com","subject":"Buy milk","text":"and eggs on the way home"}'
```
