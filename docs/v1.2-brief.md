# Obsidian-X — v1.2 brief: capture, hardened

Builds on v1.1's capture→classify→store→vault→ask loop. Goal: capturing is
effortless and never lossy. Same hard constraints as v1.1 (OpenRouter is the only
model key; embeddings via the `gte-small` edge function; single owner; boring choices).

## What ships in v1.2
1. **Cleanup** — tidy rambly text into a clean note body (keep original in `raw`).
2. **Split one → many** — a capture with several distinct thoughts becomes several items.
3. **Confidence + review** — the model scores its own certainty; low confidence (or a
   likely duplicate) marks the item `needs_review` instead of silently auto-filing.
4. **Due-date-from-language** — "next Tuesday", "in 3 days" → a real `due_at`.
5. **People/entity extraction** — pull people/places/orgs into `entities`.
6. **Auto-link** — connect each new note to its most similar existing notes (`links[]`).
7. **Dedup detection** — flag a near-identical existing note as a merge candidate (never auto-merge — non-lossy).
8. **Review inbox** — a surface to approve / merge / split the flagged items.
9. **Offline capture queue** — captures made offline are queued locally and synced when back online.
10. **Forward-to-brain email** — a private address; forwarded mail runs the capture pipeline. *(Access gate: needs an inbound-email provider decision.)*

## Schema (migration 0002, additive + idempotent)
- `raw text` (original pre-cleanup text), `due_at timestamptz`, `confidence real`,
  `needs_review boolean`, `review_reason text`, `entities jsonb`, `dup_candidate uuid`.
- RPC `match_neighbors(query_embedding, owner, exclude_id, match_count)` returning cosine similarity (for auto-link + dedup).

## Task order (commit per task, like v1.1)
- **T1 — Enrichment pipeline + schema.** One OpenRouter call returns cleaned body,
  title, type, tags, priority, confidence, due date, entities, and a split array.
  Capture route: split → embed → neighbor search (auto-link + dup flag) → store → vault.  *(no new access)*
- **T2 — Capture UI v2.** Render possibly-multiple created items, due date, entities,
  "needs review" + duplicate flags, and linked notes.  *(no new access)*
- **T3 — Review inbox.** List `needs_review` items; approve / merge / split.  *(no new access)*
- **T4 — Offline queue.** IndexedDB queue + service-worker sync; pending indicator.  *(no new access)*
- **T5 — Forward-to-brain email.** Inbound webhook → capture pipeline.  **Access gate.**

## Out of scope (later rungs)
Feeds (Gmail/Calendar) · nightly agents · ClickUp · trust dial/rules engine ·
full synthesis · graph viz · Apple Notes import. Those are v1.3+.
